# Risk Register and Mitigations

| # | Risk | Source | Mitigation in this design | Verification |
|---|---|---|---|---|
| 1 | crates.io versions are non-deletable; a bad `cargo publish` is permanent | proposal.md:50 | `cargo publish --locked` runs only after `build-binaries` succeeds on the release tag; release-please PR is review-gated so the version is inspected before any publish. Document `cargo yank` in README as the correction path. | Dry-run publish in a manual `workflow_dispatch` (dry_run) before the first real tag; yank doc in README. |
| 2 | GHCR org-scoped push may fail: `ghcr.io/dallay/organiza` requires org-level package write, but `GITHUB_TOKEN` is repo-scoped | proposal.md:51 | agentsync parity: login to GHCR with `github.repository_owner` + `GITHUB_TOKEN`. If the org rejects it, fall back to a fine-grained PAT (`GHCR_PAT`) with `packages:write` scoped to `dallay/organiza`, used only in the `publish-docker` login step. | First release: confirm both `docker pull yacosta738/organiza` and `docker pull ghcr.io/dallay/organiza` resolve; if GHCR 403s, add `GHCR_PAT` secret and rerun the docker job only. |
| 3 | Missed hardcoded `file-organizer` references (src, docs, launchers, agentsync source) | proposal.md:52 | Rename map is exhaustive (index.md §8): clap name, crate refs, env vars `ORGANIZA_CONFIG`/`ORGANIZA_DOWNLOADS`, config dir, lock path, 3 launchers, agentsync.toml, README. `.agents/AGENTS.md` is edited via `.agents/agentsync.toml` + `agentsync apply` — the CI drift job (`ci.yml` agentsync status --json) fails if the generated file diverges. | Post-rename grep gate: `grep -rn "file-organizer" --exclude-dir=.git --exclude-dir=openspec .` must match only repo-name/history (README repo URL is allowed); local `npx @dallay/agentsync apply` + `agentsync status --json` passes. |
| 4 | npm provenance/OIDC misconfiguration breaks `npm publish --provenance` | config.yaml rules; ADR-2 | `publish-npm-binaries`/`publish-npm-base` declare `permissions: { contents: read, id-token: write }`; Node 24 runner; registry-url npmjs. Provenance requires the OIDC id-token — a missing permission fails the job loudly rather than publishing unsigned. | First publish: check npmjs package page for the provenance badge; `npm publish --dry-run` in a scratch job if uncertain. |
| 5 | release-please first-run: no prior tags, manifest seeded at 0.1.0 — first release PR version may surprise | ADR-5 | Manifest `{ ".": "0.1.0" }` matches current `Cargo.toml`. Treat the FIRST release-please PR as a version-decision point: review the computed next version and the diff of all 8 version references before merging. Never merge the release-please PR accidentally (rollback plan, proposal.md:55). | `release-please-action` dry-run via `workflow_dispatch`; inspect generated PR diff before approving. |
| 6 | Existing users' configs/locks live at `file-organizer` paths; rename orphans them (no auto-migration) | proposal.md:17 (out of scope) | README "migration" callout: move `~/.config/file-organizer/config.toml` → `~/.config/organiza/`, drop `~/.cache/file-organizer.lock`, update scheduler installs. Launchers rename atomically with the binary; revert restores prior behavior (proposal.md:56). | Manual smoke on a machine with a real config: `organiza validate-config` after the move; scheduler tick runs. |
| 7 | Secrets preconditions: `NPM_TOKEN`, `CARGO_REGISTRY_TOKEN`, `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`, `APP_ID`, `APP_PRIVATE_KEY` missing → publish jobs fail post-tag | proposal.md:61 | Document the six secrets in README release section + repo settings checklist. The GitHub App token is generated inside the workflow (`create-github-app-token`), so only `APP_ID`/`APP_PRIVATE_KEY` need storing. All publish jobs run only when `new_release_created == 'true'`, so a missing secret fails that release but leaves binaries/assets published (partial state is recoverable by rerunning the failed job). | `gh secret list` audit before the first release; dry_run dispatch validates token plumbing without publishing. |
| 8 | PR exceeds the 400-line review budget | proposal.md:53; review workload guard | ADR-9: PR1 = rename + metadata + docs (≈250–350 lines, build green, drift job passes); PR2 = pipeline + npm + Docker (additive only). Chained PRs, each with autonomous scope and rollback (git revert). No release tag can be created before PR1 merges. | PR1: `cargo fmt --check` + `cargo clippy -D warnings` + `cargo test` + agentsync drift. PR2: `actionlint` (if available) or manual review of the workflow; both PRs' line counts logged in the PR description. |
| 9 | Template envsubst fragility: `bin` executable bit lost or zero/ambiguous archives matched → broken platform package ships | ADR-3/ADR-8 | Port agentsync's guards verbatim: exactly-one-archive assertion, post-extraction binary `-f` check, `npm pack` + `tar -tzvf` regex for the owner-execute bit before `npm publish`. | Platform publish step fails (non-zero) before any npm publish if a guard trips; smoke: `npm i -g @dallay/organiza@<v>` then `organiza --help` on each of the 3 OS families after the first release. |
| 10 | `.gitignore` additions land INSIDE the AgentSync managed block and get wiped/regenerated | AGENTS.md (repo root) | Add `npm/**/node_modules/`, `npm/organiza/lib/`, `npm/organiza/*.tgz` OUTSIDE the `# START AI Agent Symlinks` … `# END` markers (precedent: `target/`, `.DS_Store`). Drift job guards the managed block. | `git status` clean after `agentsync apply`; drift job green. |
